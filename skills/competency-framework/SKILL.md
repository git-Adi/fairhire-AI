# Competency Framework

Use ONLY the competencies listed below. Do not invent new ones.

## How to use this skill

**When analysing a job description**

1. Pick the 4-6 competencies that matter most for the role.
2. Give each a weight between 0.05 and 0.5. Weights must add up to 1.0.
3. Set the `required_level` (1-4) for each, using the level guide in `levels.md`.
4. List the must-have skills exactly as the JD states them.

**When designing interview questions**

- Aim questions at the level the role requires, not above it.
- Use the "evidence of this level" column in `levels.md` to describe what a good answer looks like.

## Competency catalogue

| Competency           | Covers                                                                 |
| -------------------- | ---------------------------------------------------------------------- |
| Programming          | Writing clean, tested, maintainable code (Python, Java, Go, etc.)      |
| ML & Modelling       | Classical ML, deep learning, feature engineering, evaluation           |
| GenAI & LLMs         | Prompting, RAG, agents, fine-tuning, LLM evaluation                    |
| Data Engineering     | Pipelines, SQL, Spark, data quality, warehousing                       |
| Cloud & MLOps        | AWS/GCP/Azure, Docker, Kubernetes, CI/CD, model serving and monitoring |
| System Design        | Architecture, scalability, reliability, trade-off reasoning            |
| Frontend Engineering | React, TypeScript, UI performance, accessibility                       |
| Communication        | Explaining technical work, documentation, stakeholder management       |
| Leadership           | Mentoring, ownership, driving cross-team initiatives                   |

## Rules

- Never weight or level a competency using personal attributes (age, gender, family status, nationality, religion, appearance).
- Years of experience are a weak signal. Prefer demonstrated scope and impact.
